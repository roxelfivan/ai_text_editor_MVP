# v0.4.1 — Comment / Send to AI: whole-document consistency, fewer tokens

A focused patch on top of v0.4.0. The "Send to AI" flow that batches
inline comments into one chat turn is now explicitly required to keep
its fixes consistent with the rest of the document, and the per-turn
prompt is materially cheaper — typically ~70% fewer tokens on a long
document with a handful of comments — without losing any of the
byte-exact anchoring that the proposed-edit fence schema depends on.

* **Whole-document consistency is now a first-class requirement.** The
  comment-batch system note pushed alongside the user's message no
  longer says "address each `[id]` independently" (which actively
  worked against cross-comment consistency). It now spells out three
  explicit rules: every replacement must stay consistent in voice,
  terminology, character names, facts, numbers, and style with the
  rest of the document; if a fix in one `[id]` logically requires a
  corresponding change in another `[id]` or elsewhere, the model must
  emit an *additional* proposed-edit fence for it; and if two `[id]`s
  conflict, the model should prioritize the one that keeps the
  document internally coherent and note the conflict in its prose.

* **Per-comment blocks now carry local context.** The user message
  body emitted by `formatCommentBatch` was just
  `[cN] "snippet" / Comment: body`. Each block now also carries the
  paragraph index (`paragraph P of M`) and the byte-offset range
  (`doc offset S–E`), plus a 120-character context window trimmed at
  word boundaries on each side of the snippet. That gives the model a
  stable position in the document without forcing it to fuzzy-match
  the snippet back into the full text — so fixes stay anchored even
  when many comments are sent at once on a long document.

* **Document is delivered as a structural outline, not a verbatim
  blob.** The `sys-current-doc` system message used to be the entire
  document body sandwiched between `--- BEGIN/END DOCUMENT ---`
  fences, which costs O(document size) on every chat turn. It now
  emits a compact outline — one `[pN] offset S–E: <first 60 chars>`
  line per paragraph, plus a length / paragraph count header — which
  is typically 95%+ smaller while still giving the model enough
  structural information to resolve the per-comment paragraph
  references. The verbatim document is no longer inlined at all on
  comment-batch turns (the per-comment context windows already carry
  the local content the model needs to make byte-exact `original`
  matches).

* **Proposed-edit fence schema is now its own system message.** The
  rules block used to be appended to the same system message as the
  document. It's now extracted into a `sys-proposed-edit-rules`
  message, which keeps it as a stable contract independent of the
  document and the user's customizable system prompt.

* **Token-budget discipline.** The comments-batch system note ends
  with an explicit "do not quote or mention the context windows in
  your reply" instruction, so the model doesn't pay the new context
  back out as added response tokens.
