# v0.4.5 — Comment rounds, edit rationales, leaner prompts

Feature release on top of v0.4.1. Comments now keep a multi-round
history with AI rationales after Apply; Settings can edit the
rationale format; Apply re-anchors the highlight to the adopted text;
prompts are shorter; **Predict** starts off.

* **Comment rounds + rationale history.** Each comment stores an
  ordered `rounds[]` (oldest first). Editing the body after **Send to
  AI** appends a new round instead of overwriting the last one. When
  you **Apply** a proposed edit, the AI's `rationale` is recorded on
  that round with summary, original, and replacement. The comment
  popover's **Rationale** section lists every round; each is
  independently expandable (`+` / `−`) and shows the round's comment,
  anchored text, and applied diffs.

* **`rationale` on proposed-edit fences.** The schema requires a
  `rationale` field. Default Rationale Rules ask for ≥7 numbered
  points (`1`, `2`, `3a`, `3b`, `3c`, `4`, `5`), ≥100 words total, with
  `3a`–`3c` each ≥30 words (why / paragraph / document). Override the
  rules in **Settings** without losing the JSON schema.

* **Settings: System Message + Rationale Rules.** Both are editable,
  resizable with the modal, and have **Reset** to built-in defaults.
  Custom rationale rules replace only the rationale section; the
  proposed-edit fence schema stays fixed.

* **Apply re-anchors to the replacement.** After Apply (or Apply All),
  the comment highlight and editor selection cover the adopted text
  exactly. Re-anchoring prefers the applied replacement so fuzzy
  head/tail matching cannot widen the mark.

* **Leaner prompts.** Fixed system / schema / rationale / comment-batch
  overhead cut by ~50% while keeping the same contracts (byte-exact
  `original`, consistency rules, outline-only doc context).

* **Predict off by default.** Inline completion stays off until you
  click **Predict** (or `⌘/Ctrl + \\`).
