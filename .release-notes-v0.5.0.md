# v0.5.0 — Export Markdown, import size caps, best-effort Apply, file-actions alignment

Feature release on top of [v0.4.9](https://github.com/roxelfivan/apeditor/releases/tag/v0.4.9). Three user-visible wins from the UX roadmap ([ux-enhancement-plan-fba2](https://github.com/roxelfivan/apeditor/blob/cursor/ux-enhancement-plan-fba2/tmp/ux-enhancement-phases.md)) — Export Markdown, import size / page caps with friendly errors, and a one-click best-effort Apply for mismatched AI quotes — plus a follow-up alignment pass on the new Import / Export popover and a rename of the toolbar component from `ImportMediaButton` to `FileActionsButton` (since the button now exposes both directions, not just Import). One new doc (`docs/UX_SLICE_1.md`) captures the slice design rationale.

## Added

- **Export Markdown.** A new **Export .md** button in the file-actions popover (the editor toolbar button formerly labelled "Import") downloads the current document as a Markdown file. Filename is the document title, sanitised; defaults to `untitled.md`. This is the only durable off-tab backup of your writing today — `localStorage` can be wiped by browser data clearing, private-mode expiry, or quota eviction, with no warning. The download helper (`downloadTextFile` + `sanitizeFilename` in `src/utils/storage.ts`) is the foundation for a future JSON backup that includes comments, chat history, and revisions.
- **Inline confirmation prompt for best-effort Apply.** When the AI's `original` quote can't be matched in the current document by any of the six existing strategies (exact / trimmed / whitespace-collapsed / Setext heading / ATX-prefix / markdown-escape), Apply no longer silently fails. A new `findBestEffortAnchor` utility in `src/utils/proposedEdit.ts` runs a token-overlap match with an adaptive lookahead, a skip budget, and a 100 KB content cap. If it finds a candidate, the card shows an inline alert with the matched passage and a confidence percentage; the user confirms or cancels before any text changes. The Apply button stays enabled whenever EITHER a strict OR a best-effort match is available, with the tooltip reflecting which path will run. Algorithm validated against 10 smoke tests covering near-miss, reflow, swapped words, partial overlap, middle-match, and common-word false-positive guard.

## Changed

- **Import size and page caps.** Imports now refuse with a friendly inline error before doing any heavy work if any file is over 50 MB, the batch is over 200 MB total, or a PDF has more than 500 pages. Previously the OCR pipeline read the entire PDF into memory and rasterised every page, which could freeze or evict the tab on a multi-hundred-page scan. The errors surface through the existing red inline-error UI in the file-actions popover and match the design vocabulary of the other inline messages.
- **File-actions popover alignment.** The Export and Import sections inside the popover now share the same structural template (section header → two-sentence description → primary-CTA action button row aligned right). The Export button was upgraded from `btn-ghost-sm` (tertiary, muted) to `btn-fire-sm` (primary CTA) so both sections have visually identical primary actions. The `Close` button stays `btn-cyan-sm` as the secondary cancel for the whole popover.
- **Toolbar icon reframed.** The down-arrow-into-tray glyph (which read as "Import only") is replaced by a page-with-arrows glyph: a small page outline flanked by an up arrow (Export) on the left and a down arrow (Import) on the right. The icon is direction-neutral — it now reads as "this button handles files in and out for a document" without picking a direction. The toggle's `aria-label` and `title` were updated in lockstep to mention both actions.

## Renamed

- **`ImportMediaButton` → `FileActionsButton`** (component + file). The old name stopped being accurate when the popover gained a second action; the rename is purely a name correction, no behaviour change. `git mv` preserves blame history (78 % similarity). All doc references in `README.md`, `RELEASE_NOTES.md`, `docs/ARCHITECTURE.md`, `docs/REFACTORING.md`, `docs/UX_SLICE_1.md` are updated to the new name, with `(formerly ImportMediaButton)` breadcrumbs so the old name stays grep-fable. The `ImportMediaButtonProps` interface name is kept — the props are unchanged and no consumer differentiates by type name.
- **Popover reorder: Import first, Export second.** Import is the button's primary semantic identity (the toolbar button has always been labelled around it), so Import is the top section and Export is below the divider. Both sections have the same visual weight (identical button style, identical action row alignment).
- **`data-import-media-toggle` → `data-file-actions-toggle`.** Single internal selector used by the outside-click handler; no public API impact.

## Behaviour that did NOT change

- The six existing `findEditAnchor` strategies (preserved verbatim).
- The Force-apply path — still the right escape hatch when no anchor of any kind is available.
- Apply All in `ChatPanel` — still reports `"Applied x of y changes (z skipped — not anchored)"` for batches. Per-skipped "Apply individually" link is queued for the next slice.
- The **Potential mismatch detected** warning UI on `ProposedEditCard` — kept; only the inline message copy is now conditional on whether a best-effort is available.
- All prompt, store, and LLM-facing contracts.
- All other toolbar buttons.

## Internal

- **`src/utils/storage.ts`** — added `downloadTextFile` (Blob + `URL.createObjectURL` + invisible anchor click; SSR-safe; cleans up on next tick) and `sanitizeFilename` (strips path separators and reserved chars, collapses whitespace, caps length to 80, falls back to `"untitled"`). Comment-level rationale captured in JSDoc above each helper.
- **`src/utils/ocr.ts`** — added `validateOcrBatch`, `formatOcrSize`, and three module-level limit constants (`OCR_MAX_FILE_BYTES`, `OCR_MAX_PDF_PAGES`, `OCR_MAX_BATCH_BYTES`). `extractTextFromFiles` runs the batch validator first; `extractFromPdfFile` checks `pdf.numPages` after the document loads. The outer `pdf.destroy()` still runs in both the success and error paths so worker-side buffers are released.
- **`src/utils/proposedEdit.ts`** — added `findBestEffortAnchor` (≈100 LOC of algorithm + comments) and the `BestEffortAnchor` type. The existing `applyEdit`, `applyEditAtCaret`, `applyAllEdits`, `findEditAnchor`, `parseProposedEdits`, and `formatRejectionBatch` are untouched.
- **`src/components/FileActionsButton.tsx`** (formerly `src/components/ImportMediaButton.tsx`) — added `useCurrentDocument()` import, `onExportClick` handler, and an Export section in the popover. Alignment pass: both section primary actions use `btn-fire-sm`, descriptions follow the same two-sentence template, and the toolbar SVG was redrawn as a page-with-arrows glyph. The component was renamed because the toolbar button now exposes both Import and Export actions, not just Import; the `aria-label` / `title` / `data-file-actions-toggle` selector were updated in lockstep.
- **`src/components/ProposedEditCard.tsx`** — added `bestEffortAnchor` memo, `pendingBestEffort` state + stale-span effect, `performReplace` helper (shared by the strict and best-effort paths), `handleConfirmBestEffort` / `handleCancelBestEffort` handlers, and the confirmation prompt JSX. The strict `handleApply` now routes to `performReplace` on success or sets `pendingBestEffort` on a missing best-effort (down from a silent no-op). The `disabled` flag is recomputed so the Apply button is enabled whenever either path is viable.
- **`docs/UX_SLICE_1.md`** — new document capturing the full slice design, items from the roadmap that were deliberately NOT in scope (doc-drift fix already shipped in v0.4.9; soft secret redaction deferred in favour of session-only key), and what's queued for the next slice.

## Verification

- `npx tsc --noEmit -p tsconfig.app.json` — clean.
- `npm run build` — succeeds in ~11 s; bundle size unchanged.
- `findBestEffortAnchor` smoke tests — 10 / 10 pass (too-short, too-few-tokens, no-overlap, one-word near miss, reflow, exact, swapped words, partial overlap, middle match with leading garbage, common-word false-positive guard).
- Manual (recommended before next session):
  - Click the toolbar button → confirm the popover shows Import (top) and Export (bottom) sections with the same visual rhythm; both primary buttons are `btn-fire-sm`.
  - Click **Export .md** → confirm the file downloads with the document's filename.
  - Try a 50+ MB import or a 600-page PDF → confirm the inline error appears and no work is done.
  - Edit a paragraph in your document AFTER the AI has produced a proposed edit on it → click Apply → confirm the inline confirmation prompt appears with the matched passage and a confidence percentage. Cancel returns to the card unchanged; Replace splices the new text.
