# v0.5.0 — Export Markdown, import size caps, best-effort Apply

Feature release on top of [v0.4.9](https://github.com/roxelfivan/apeditor/releases/tag/v0.4.9). Three user-visible wins from the UX roadmap ([ux-enhancement-plan-fba2](https://github.com/roxelfivan/apeditor/blob/cursor/ux-enhancement-plan-fba2/tmp/ux-enhancement-phases.md)) — Export Markdown, import size / page caps with friendly errors, and a one-click best-effort Apply for mismatched AI quotes — plus one new doc (`docs/UX_SLICE_1.md`) that captures the design rationale.

## Added

- **Export Markdown.** A new **Export .md** button at the top of the Import popover (in the editor toolbar) downloads the current document as a Markdown file. Filename is the document title, sanitised; defaults to `untitled.md`. This is the only durable off-tab backup of your writing today — `localStorage` can be wiped by browser data clearing, private-mode expiry, or quota eviction, with no warning. The download helper (`downloadTextFile` + `sanitizeFilename` in `src/utils/storage.ts`) is the foundation for a future JSON backup that includes comments, chat history, and revisions.
- **Inline confirmation prompt for best-effort Apply.** When the AI's `original` quote can't be matched in the current document by any of the six existing strategies (exact / trimmed / whitespace-collapsed / Setext heading / ATX-prefix / markdown-escape), Apply no longer silently fails. A new `findBestEffortAnchor` utility in `src/utils/proposedEdit.ts` runs a token-overlap match with an adaptive lookahead, a skip budget, and a 100 KB content cap. If it finds a candidate, the card shows an inline alert with the matched passage and a confidence percentage; the user confirms or cancels before any text changes. The Apply button stays enabled whenever EITHER a strict OR a best-effort match is available, with the tooltip reflecting which path will run. Algorithm validated against 10 smoke tests covering near-miss, reflow, swapped words, partial overlap, middle-match, and common-word false-positive guard.

## Changed

- **Import size and page caps.** Imports now refuse with a friendly inline error before doing any heavy work if any file is over 50 MB, the batch is over 200 MB total, or a PDF has more than 500 pages. Previously the OCR pipeline read the entire PDF into memory and rasterised every page, which could freeze or evict the tab on a multi-hundred-page scan. The errors surface through the existing red inline-error UI in the Import popover and match the design vocabulary of the other inline messages.

## Behaviour that did NOT change

- The six existing `findEditAnchor` strategies (preserved verbatim).
- The Force-apply path — still the right escape hatch when no anchor of any kind is available.
- Apply All in `ChatPanel` — still reports `"Applied x of y changes (z skipped — not anchored)"` for batches. Per-skipped "Apply individually" link is queued for the next slice.
- The **Potential mismatch detected** warning UI on `ProposedEditCard` — kept; only the inline message copy is now conditional on whether a best-effort is available.
- All prompt, store, and LLM-facing contracts.

## Internal

- **`src/utils/storage.ts`** — added `downloadTextFile` (Blob + `URL.createObjectURL` + invisible anchor click; SSR-safe; cleans up on next tick) and `sanitizeFilename` (strips path separators and reserved chars, collapses whitespace, caps length to 80, falls back to `"untitled"`). Comment-level rationale captured in JSDoc above each helper.
- **`src/utils/ocr.ts`** — added `validateOcrBatch`, `formatOcrSize`, and three module-level limit constants (`OCR_MAX_FILE_BYTES`, `OCR_MAX_PDF_PAGES`, `OCR_MAX_BATCH_BYTES`). `extractTextFromFiles` runs the batch validator first; `extractFromPdfFile` checks `pdf.numPages` after the document loads. The outer `pdf.destroy()` still runs in both the success and error paths so worker-side buffers are released.
- **`src/utils/proposedEdit.ts`** — added `findBestEffortAnchor` (≈100 LOC of algorithm + comments) and the `BestEffortAnchor` type. The existing `applyEdit`, `applyEditAtCaret`, `applyAllEdits`, `findEditAnchor`, `parseProposedEdits`, and `formatRejectionBatch` are untouched.
- **`src/components/ImportMediaButton.tsx`** — added `useCurrentDocument()` import, `onExportClick` handler, and an "Export" section at the top of the popover (above OCR settings). The existing OCR language picker, file picker, progress UI, and error UI are unchanged.
- **`src/components/ProposedEditCard.tsx`** — added `bestEffortAnchor` memo, `pendingBestEffort` state + stale-span effect, `performReplace` helper (shared by the strict and best-effort paths), `handleConfirmBestEffort` / `handleCancelBestEffort` handlers, and the confirmation prompt JSX. The strict `handleApply` now routes to `performReplace` on success or sets `pendingBestEffort` on a missing best-effort (down from a silent no-op). The `disabled` flag is recomputed so the Apply button is enabled whenever either path is viable.
- **`docs/UX_SLICE_1.md`** — new document capturing the full slice design, items from the roadmap that were deliberately NOT in scope (doc-drift fix already shipped in v0.4.9; soft secret redaction deferred in favour of session-only key), and what's queued for the next slice.

## Verification

- `npx tsc --noEmit -p tsconfig.app.json` — clean.
- `npm run build` — succeeds in ~11 s; bundle size unchanged.
- `findBestEffortAnchor` smoke tests — 10 / 10 pass (too-short, too-few-tokens, no-overlap, one-word near miss, reflow, exact, swapped words, partial overlap, middle match with leading garbage, common-word false-positive guard).
- Manual (recommended before next session):
  - Open the Import popover → click **Export .md** → confirm the file downloads with the document's filename.
  - Try a 50+ MB import or a 600-page PDF → confirm the inline error appears and no work is done.
  - Edit a paragraph in your document AFTER the AI has produced a proposed edit on it → click Apply → confirm the inline confirmation prompt appears with the matched passage and a confidence percentage. Cancel returns to the card unchanged; Replace splices the new text.
